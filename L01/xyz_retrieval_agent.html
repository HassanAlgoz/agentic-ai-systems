Build a custom RAG agent with LangGraph

Open In Colab

Overview

In this tutorial, we will explore how to build an intelligent, custom Retrieval-Augmented Generation (RAG) agent using the newly introduced functional API from LangGraph.

RAG agents are a critical step up from simple retrieval pipelines: instead of always retrieving documents regardless of the context, a retrieval agent first decides whether it needs to retrieve information at all. If it does, it searches for context, grades the relevance of what it found, and uses it to answer. If it doesn’t need external information, it will respond directly.

By the end of this tutorial, you will have built a RAG agent capable of:

  1. Fetching and preprocessing documents.
  2. Indexing documents for semantic search.
  3. Supplying an external retriever as a tool to an AI model.
  4. Using LangGraph’s @entrypoint and @task functional API to orchestrate intelligent decision-making, grading, and query rewriting without needing complex graph state definitions.

Since full documents are often too large to fit effectively into an LLM context window without diluting relevance, we split them into smaller, overlapping chunks.

from langchain_text_splitters import RecursiveCharacterTextSplitter

docs_list = [item for sublist in docs for item in sublist]

text_splitter = RecursiveCharacterTextSplitter.from_tiktoken_encoder(
    chunk_size=100, chunk_overlap=50
)
doc_splits = text_splitter.split_documents(docs_list)

2. Create an embedding and indexing pipeline

Now that we have our document chunks, we index them into a vector store. We use HuggingFace embeddings (sentence-transformers/all-mpnet-base-v2) so the tutorial runs without an API key. For production you can switch to OpenRouter or another provider (see OpenRouter embeddings).

from langchain_core.vectorstores import InMemoryVectorStore
from langchain_huggingface import HuggingFaceEmbeddings

# Local embeddings (no API key). For OpenRouter, use OpenAIEmbeddings with base_url and a supported embed model.
embeddings_model = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-mpnet-base-v2"
)

vectorstore = InMemoryVectorStore.from_documents(
    documents=doc_splits,
    embedding=embeddings_model
)
retriever = vectorstore.as_retriever()

We wrap our retriever into a standard LangChain @tool so our agent can dynamically route queries to it.

from langchain_core.tools import tool

@tool
def retrieve_blog_posts(query: str) -> str:
    """Search and return information about Lilian Weng blog posts."""
    docs = retriever.invoke(query)
    return "\n\n".join([doc.page_content for doc in docs])

3. Configure the Agent Model

To reason and take action, we will initialize our response model. We’re using the lightweight and effective nemotron-3-nano model hosted by Nvidia via OpenRouter.

from langchain_openai import ChatOpenAI

# https://openrouter.ai/nvidia/nemotron-3-nano-30b-a3b:free
model_nemotron3_nano = ChatOpenAI(
    model="nvidia/nemotron-3-nano-30b-a3b:free",
    temperature=0,
    # OpenRouter instead of the default OpenAI API
    base_url="https://openrouter.ai/api/v1",
    api_key=os.environ.get("OPENROUTER_API_KEY"),
)

4. Defining LangGraph Tasks

LangGraph’s Functional API allows us to express complex control flows smoothly using standard Python primitives like @entrypoint and @task. We don’t have to lump all our workflow logic simultaneously into a giant graph anymore.

Let’s build out the discrete capabilities (tasks) our agent will perform.

Generate Query or Respond

Our first task calls the LLM. It analyzes the chat history so far and decides whether to fetch more documents using the retrieve_blog_posts tool, or just reply back directly to the user.

from langgraph.func import task

@task
def generate_query_or_respond(messages):
    """Decide to retrieve or simply respond."""
    response = (
        model_nemotron3_nano
        .bind_tools([retrieve_blog_posts])
        .invoke(messages)
    )
    return response

Grade Documents

Once documents are retrieved, we shouldn’t blindly trust them. This task inspects the retrieved documents to assess if they are strictly relevant to the user’s question. We enforce a structured output to get a clean “yes/no” result.

from langchain.messages import HumanMessage
from pydantic import BaseModel, Field

GRADE_PROMPT = (
    "You are a grader assessing relevance of a retrieved document to a user question. \n "
    "Here is the retrieved document: \n\n {context} \n\n"
    "Here is the user question: {question} \n"
    "If the document contains keyword(s) or semantic meaning related to the user question, grade it as relevant. \n"
    "Give a binary score 'yes' or 'no' score to indicate whether the document is relevant to the question."
)

class GradeDocuments(BaseModel):
    """Grade documents using a binary score for relevance check."""
    binary_score: str = Field(
        description="Relevance score: 'yes' if relevant, or 'no' if not relevant"
    )

@task
def grade_documents(question: str, context: str):
    """Determine whether the retrieved documents are relevant to the question."""
    prompt = GRADE_PROMPT.format(question=question, context=context)
    response = (
        model_nemotron3_nano
        .with_structured_output(GradeDocuments)
        .invoke([HumanMessage(prompt)])
    )
    return response.binary_score

Rewrite Question

If the retrieved documents fail the grading check, it usually indicates the user query was too vague or poorly formulated. This task uses the LLM to rewrite the query into an improved version to be used for the next retrieval attempt.

from langchain_core.messages import HumanMessage

REWRITE_PROMPT = (
    "Look at the input and try to reason about the underlying semantic intent / meaning.\n"
    "Here is the initial question:\n ------- \n{question}\n ------- \n"
    "Formulate an improved question:"
)

@task
def rewrite_question(question: str):
    """Rewrite the original user question."""
    prompt = REWRITE_PROMPT.format(question=question)
    response = model_nemotron3_nano.invoke([HumanMessage(prompt)])
    return response.content

Generate Final Answer

If the grader accepts the retrieved documents, they are passed to this final task alongside the original query. The LLM then distills the final, concise answer.

GENERATE_PROMPT = (
    "You are an assistant for question-answering tasks. "
    "Use the following pieces of retrieved context to answer the question. "
    "If you don't know the answer, just say that you don't know. "
    "Use three sentences maximum and keep the answer concise.\n"
    "Question: {question} \n"
    "Context: {context}"
)


@task
def generate_answer(question: str, context: str):
    """Generate the final synthesized answer."""
    prompt = GENERATE_PROMPT.format(question=question, context=context)
    response = model_nemotron3_nano.invoke([HumanMessage(prompt)])
    return response.content

5. Assemble the Workflow with entrypoint

Using @entrypoint, we can weave these individual tasks into a cohesive loop using completely standard Python logic like while, if, and return. This avoids the friction of explicit, complicated static graph edges.

The workflow begins by trying to generate a query or respond. If it needs to use a tool, it calls the retrieve tool and grades the output. Depending on the grade, we either generate a final answer and stop or rewrite the user’s question and loop again!

def get_last_user_message(messsages: list):
    """reliably find the initial user question"""
    # LangChain messages come in two formats that aren't directly interchangeable:
    # - **`BaseMessage` instances** (e.g., `HumanMessage`, `AIMessage`): Have `.type == "human"` and `.content`
    # - **Raw `dict`s** (from LangSmith traces, APIs, or external sources): Have `"role": "user"` and `"content"`
    last_message = next(
        msg.content if hasattr(msg, "content") else msg["content"]
        for msg in reversed(messsages)
        if (hasattr(msg, "type") and msg.type == "human") or (isinstance(msg, dict) and msg.get("role") == "user")
    )
    return last_message
from langgraph.func import entrypoint
from langchain_core.messages import ToolMessage, AIMessage

@entrypoint()
def agent_workflow(messages: list):
    # Keep a local copy of our message history
    current_messages = list(messages)
    
    # We reliably find the initial user question
    question = get_last_user_message(current_messages)
    
    # Optional logic: Limit iterations to avoid endless loops
    max_retries = 3
    retries = 0

    while retries < max_retries:
        # 1. Ask the model whether to reply or retrieve
        response = generate_query_or_respond(current_messages).result()
        current_messages.append(response)

        # Base case: Model decides to reply cleanly without tools
        if not response.tool_calls:
            return {"messages": current_messages}

        # 2. Extract tool instructions and Retrieve
        tool_call = response.tool_calls[0]
        tool_response = retrieve_blog_posts.invoke(tool_call)
        
        # Append tool message output to chat state
        current_messages.append(
            ToolMessage(tool_response, tool_call_id=tool_call["id"])
        )

        # 3. Grade the retrieved documents
        score = grade_documents(question, tool_response).result()

        # 4. Success path: Context is relevant, generate the answer and end
        if score == "yes":
            answer = generate_answer(question, tool_response).result()
            current_messages.append(
                AIMessage(answer)
            )
            return {"messages": current_messages}

        # 5. Fallback path: Context was irrelevant, let's rewrite the query
        else:
            rewritten_q = rewrite_question(question).result()
            # Feed the rewritten question into the model history as a new attempt
            current_messages.append(
                HumanMessage(rewritten_q)
            )
            question = rewritten_q
            retries += 1
            
    # Default end if retries are exhausted
    return {"messages": current_messages}

6. Run the agentic RAG

We can now test the fully orchestrated workflow. With LangGraph’s Functional API, the @entrypoint acts as an invokable pipeline, and we can directly invoke it to observe the outputs!

# Run the full orchestrated workflow
final_state = agent_workflow.invoke([
    HumanMessage("What does Lilian Weng say about types of reward hacking?")
])
for message in final_state['messages']:
    message.pretty_print()

Key Takeaways

  • RAG Agents vs Pipelines: Unlike static retrieval chains that retrieve every time regardless of context, a RAG Agent has autonomy. It actively decides if it should search for documents and grades the results before proceeding.
  • LangGraph Functional API: The combination of @entrypoint and @task moves workflow orchestration out of strict graph edge definitions and into natural Python control structures like while and if/else, vastly improving readability and code simplicity.
  • Graceful Degradation: By utilizing query rewriting (rewrite_question), the agent acts on its own self-reflection instead of just throwing bad context into a final prompt, leading to dramatically higher success rates in QA applications.
  • Separation of Concerns: Writing distinct functions for generate_answer, grade_documents, and rewrite_question allows each piece to be evaluated independently, tested rigorously, and customized for individual model quirks without muddying a single prompt.
