Multi-Agent Customer Support with Handoffs and Human Escalation

What we’re building

We build a multi-agent customer support system where:

  • Sales and Support are separate agents; each handles its domain and can hand off to the other via tool calls.
  • Either agent can escalate a case to a human. The graph pauses (using LangGraph’s interrupt), a human provides input, and the graph resumes with that input.

This is a natural fit for front desks that route between sales and support and need the option to pull in a human for complex or sensitive cases.

Relation to the single-agent notebook

This notebook is a spin-off of Build customer support agent, which uses one agent and a state machine: a single LLM advances through steps (warranty → issue type → resolution) by changing system prompt and tools.

Here we use multiple agents and handoffs: Sales and Support are distinct nodes; control moves between them via handoff tools.

1. Hand-offs between agents

We use tool calls (e.g. transfer_to_sales_agent, transfer_to_support_agent) to move control between agents. The term handoffs is used by OpenAI for this pattern.

Why pairing matters: When we hand off, the next agent sees the same messages list. LLMs expect every tool call to have a corresponding tool result. If we only updated routing state and didn’t add a synthetic tool result, the receiving agent would see an unpaired tool call and can error or behave oddly.

What to do:

  1. Return a Command with graph=Command.PARENT and goto=next_agent.
  2. In update["messages"] append:
    • The AIMessage that contains the handoff tool call.
    • A ToolMessage that acknowledges the handoff (so the tool call is “paired” with a result).

That way the receiving agent gets a valid conversation history.

from typing import Literal
from langchain.messages import AIMessage, ToolMessage
from langchain.tools import tool, ToolRuntime
from langgraph.types import Command


def handoff_to_agent(
    next_agent: Literal["sales_agent", "support_agent"],
    runtime: ToolRuntime,
) -> Command:
    """Transfer control to the specified agent. Pairs the handoff tool call with a ToolMessage."""
    # Last AI message is the one that issued the handoff tool call
    last_ai_message = next(
        msg for msg in reversed(runtime.state["messages"]) if isinstance(msg, AIMessage)
    )
    # Synthetic tool result so the conversation history stays valid for the next agent
    transfer_message = ToolMessage(
        content=f"Transferred to {next_agent}",
        tool_call_id=runtime.tool_call_id,
    )
    return Command(
        graph=Command.PARENT,
        goto=next_agent,
        update={
            "active_agent": next_agent,
            "messages": [last_ai_message, transfer_message],
        },
    )


@tool
def transfer_to_sales_agent(runtime: ToolRuntime):
    """Transfer to sales agent. Use when the user asks about pricing or purchasing."""
    return handoff_to_agent(next_agent="sales_agent", runtime=runtime)


@tool
def transfer_to_support_agent(runtime: ToolRuntime):
    """Transfer to support agent. Use when the user has technical or account issues."""
    return handoff_to_agent(next_agent="support_agent", runtime=runtime)

2. Human-in-the-loop: escalation via interrupt

When an agent decides a case needs a human (e.g. sensitive complaint, policy exception), we escalate by pausing the graph and waiting for human input. LangGraph’s interrupt() does exactly that:

  • Execution pauses at the call site; the value passed to interrupt(...) is JSON-serializable and is surfaced to the caller in result["__interrupt__"].
  • State is saved by the checkpointer; you resume later with the same thread_id by invoking the graph with Command(resume=human_response).
  • The resume value becomes the return value of interrupt() inside the tool, so we can return it as the tool result and the agent can use it in the next turn.
from langchain.tools import tool, ToolRuntime
from langgraph.types import interrupt


@tool
def escalate_to_human(reason: str, summary: str, runtime: ToolRuntime) -> str:
    """Escalate this case to a human. Use when the customer needs a human (complaint, exception, or you cannot resolve)."""
    # Pause the graph; payload appears in result["__interrupt__"] for the caller to show to a human
    payload = {
        "action": "escalate",
        "reason": reason,
        "summary": summary,
        "message": "Human input required. Resume the graph with Command(resume=<your_response>).",
    }
    human_response = interrupt(payload)
    # After resume, human_response is the value passed to Command(resume=...); return it as tool result
    if isinstance(human_response, str):
        return human_response
    # If the human passed a dict (e.g. {"action": "approved", "reply": "..."}), format it
    return str(human_response)

sales_agent = create_agent(
    model=model_nemotron3_nano,
    tools=[transfer_to_support_agent, escalate_to_human],
    system_prompt=(
        "You are a sales agent. Help with sales inquiries. "
        "If asked about technical issues or support, transfer to the support agent. "
        "If a customer needs a human (e.g. complaint or exception), use escalate_to_human with a reason and short summary."
    ),
)

# Support: hand off to sales for pricing/purchasing; can escalate to human when needed
support_agent = create_agent(
    model=model_nemotron3_nano,
    tools=[transfer_to_sales_agent, escalate_to_human],
    system_prompt=(

        "If asked about pricing or purchasing, transfer to the sales agent. "
        "If you cannot resolve or the case needs a human, use escalate_to_human with reason and summary."
    ),
)

4. Building the StateGraph

State: We extend AgentState with active_agent so the graph knows which node to route to after a handoff.

from typing_extensions import NotRequired
from langchain.agents import AgentState


class MultiAgentState(AgentState):
    """Conversation messages plus the current agent (for routing after handoffs)."""
    active_agent: NotRequired[str]
from typing import Literal
from langchain.messages import AIMessage
from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import InMemorySaver


def call_sales_agent(state: MultiAgentState):
    """Node: run the sales agent on current state (may hand off or escalate)."""
    return sales_agent.invoke(state)


def call_support_agent(state: MultiAgentState):
    """Node: run the support agent on current state (may hand off or escalate)."""
    return support_agent.invoke(state)


def route_after_agent(state: MultiAgentState) -> Literal["sales_agent", "support_agent", "__end__"]:
    """If the last message is an AI message with no tool calls, we're done; else follow active_agent."""
    messages = state.get("messages", [])
    if messages:
        last_msg = messages[-1]
        if isinstance(last_msg, AIMessage) and not last_msg.tool_calls:
            return "__end__"
    return state.get("active_agent", "sales_agent") or "sales_agent"


def route_initial(state: MultiAgentState) -> Literal["sales_agent", "support_agent"]:
    """Start at sales or support (e.g. when resuming after interrupt, active_agent may be set)."""
    return state.get("active_agent") or "sales_agent"


# Build graph: two agent nodes, conditional edges from START and after each agent
builder = StateGraph(MultiAgentState)
builder.add_node("sales_agent", call_sales_agent)
builder.add_node("support_agent", call_support_agent)
builder.add_conditional_edges(START, route_initial, ["sales_agent", "support_agent"])
builder.add_conditional_edges("sales_agent", route_after_agent, ["sales_agent", "support_agent", END])
builder.add_conditional_edges("support_agent", route_after_agent, ["sales_agent", "support_agent", END])
<langgraph.graph.state.StateGraph at 0x7b5c80a3faa0>
# Checkpointer is required for interrupt/resume; use a durable checkpointer in production
checkpointer = InMemorySaver()
graph = builder.compile(checkpointer=checkpointer)

6. Implementation considerations

As you design your multi-agent system, consider:

  • Context filtering strategy: Will each agent receive full conversation history, filtered portions, or summaries? Different agents may need different context depending on their role.
  • Tool semantics: Clarify whether handoff tools only update routing state or also perform side effects. For example, should transfer_to_sales() also create a support ticket, or should that be a separate action?
  • Token efficiency: Balance context completeness against token costs. Summarization and selective context passing become more important as conversations grow longer.
  • Human-in-the-loop: When using interrupt() for escalation, use a durable checkpointer in production and a stable thread_id so you can resume the same conversation. Decide what the human can provide (e.g. free text vs. structured approval) and document it for your operators.
